# Implement conservative APFS accounting v4

This ExecPlan is a living document and follows `/root/.agent/PLANS.md`.

## Purpose / Big Picture

The `duh` tool should report storage that is provably reclaimable without
double-counting hardlinks or overstating APFS clone savings. After this work,
its accounting cache will distinguish immediately guaranteed bytes from
conditional clone-family bytes and bytes whose reclaimability is unknown. A
reviewer can verify the result with the Rust and Python gold-test suites and,
afterward, with the native APFS probe on golf.

## Context and Orientation

`src/db.rs` declares the SQLite schema. `src/scan.rs` records per-file APFS
metadata and excluded-subtree aggregates. `src/freeable.rs` computes directory
credits, currently returning only `(freeable, locked_here)` and persisting
those values in `freeable_cache`. `finalize_family()` in that module resolves
an LCA for a family of paths. The `blackbox/` tests compare Rust behavior with
the reference Python implementation. The new `docs/apfs_semantics.md` is the
empirical source for the APFS rules in this plan.

An LCA is the deepest directory that contains all members of a family. A
guaranteed byte is proven to become physically reclaimable when the represented
deletion occurs. Conditional shared bytes become reclaimable only after the
necessary live clone members disappear. Uncertain bytes cannot be safely
assigned from the available metadata.

## Plan of Work

First inspect the schema consumers and all output paths so the public result
can remain backward-compatible where appropriate while exposing the new
dimensions. Add an explicit schema-v4 marker and reject older databases with a
clear rebuild/rescan error rather than silently reading stale columns.

Then introduce an internal accounting structure containing guaranteed,
conditional_shared, uncertain, and locked variants. Make ordinary private
single-link files contribute guaranteed bytes; group hardlinks by `(dev, ino)`
and credit their private bytes once at the hardlink LCA; use `clone_refcnt`
only for consistent full-clone families whose members report the all-blocks
flag; and classify partial-clone private components as guaranteed while
leaving their shared remainder uncertain. Excluded-subtree rows must either
carry enough metadata for this classification or explicitly contribute to
uncertain bytes.

Keep the legacy `freeable` command meaningful by defining it as the guaranteed
dimension, while JSON output and cache rows expose the additional dimensions.
Update wording so no output claims that all dimensions equal `rm -rf` reclaim
or `df` change.

Finally add tests for schema rejection, hardlink deduplication, conservative
full/partial clone classification, excluded data, and the clone-plus-hardlink
topology. Run the Rust tests and blackbox tests before native golf validation.
